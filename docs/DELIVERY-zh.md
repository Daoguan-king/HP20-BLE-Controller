## 2. 协议（全部经真机确认）
| 项 | 值 |
|---|---|
| GATT | 服务 `0000fff0`；`fff1`(notify + write-without-response) 收发共用；`fff2`(read/notify)、`fff3`(write) 备用。**APK 里的 `ff01/ff02/ffff` 在真机上不存在** |
| 帧格式 | `SOF(0xAF 请求 / 0xDF 应答) lo hi cmd len payload… LRC`；16 位设备头 = `dev_id | family<<8`，**HP20 = 0x0209**（`AF 09 02`）；总长 = 6 + len |
| LRC | `(256 - (sum(前置全部字节，含 SOF) & 0xFF)) & 0xFF` |
| 识别 | `AF 09 02 00 00 46` → `DF FF FF 00 02 09 02 16`（应答设备头 `FFFF`，按 payload `09 02` 判型号） |
| 命令 | `0x00` 识别 / `0x03` 设温(`[index,i16le]`，0–3=T1–T4，4=T5 目标) / `0x04` 读预设 / `0x05` 选挡位 / `0x06` 写回流(8×u16le) / `0x07` 读回流 / `0x08` 写名(20B) / `0x09` 读名 / `0x0A` 读状态 / `0x0B` 写维修(8×u16le) / `0x0C` 读维修 |
| 时序 | 轮询 125 ms；单命令在途；写间隔 15 ms；应答超时 2000 ms；连接总预算 45 s |
| 分包 | 跨 notify 累积、单包多帧、LRC 错帧丢弃；请求-应答按 cmd 配对 |

## 3. 状态帧字段（cmd `0x0A`，payload 11 字节）
| 偏移 | 含义 | 决定性证据 |
|---|---|---|
| `[0:2]` i16 | **当前温度 ℃** | 面板大字一致 |
| `[2]` u8 | **供电功率 W** | 换电源 65→140 同步；官方 APP 顶栏「65W」 |
| `[3:5]` u16 | **输入电压 ×0.1V** | 200→20.0V、278→27.8V |
| `[5]` u8 | **输出状态**：`0x00` 待机 / `0x02` 加热模式运行中（保温 0W 也是 0x02） | 真机两态对比 |
| `[6]` u8 | **当前输出功率 W** | 加热实测 57→125→135W，停热 0W |
| `W1=[7:9]` | `W1&0x3FF` 目标温度；`(W1>>10)&3` 挡位/阶段；`(W1>>12)&7` 模式 | 写读闭环 |
| `W2=[9:11]` | **加热计时：64 进制打包的 MM:SS**（见 3.1） | 见 3.1 的精确锚点 |

### 3.1 计时换算（64 进制打包，与面板一致）
```python
def timer_text(w2):
    mm = (w2 >> 6) & 0x7F      # 每分钟 = 64 个单位（不是 60！）
    ss =  w2       & 0x3F
    if ss >= 60:               # 0x29BF 的 SS=63 即由这条判为 OFF
        return "OFF"
    return f"{mm:02d}:{ss:02d}"
```
**精确锚点（用户真机设置值，决定性证据）**：加热超时 25 min → `W2=1600`（= 25×64）→ 显示 `25:00`；休眠时间 20 min → `W2=1280`（= 20×64）→ 显示 `20:00`；`1229 → 19:13`、`1832 → 28:40`、`0x29BF → OFF`。
> 历史误判记录：本项目曾两次把它当「总秒数」（`1600 s → 26:40`、`1280 s → 21:20`，与面板明显不符）。官方 APP 的 `MM=(w2>>6)&0x7F / SS=w2&0x3F` 实现**是对的**，现已按它实现并加反向断言（`1229` 必须得到 `19:13`）。

### 3.2 模式枚举（`(W1>>12)&7`）
| 值 | 含义 | 挡位字段含义 |
|---|---|---|
| 0 | 待机 | 上次挡位 |
| 1 | **回流焊** | 阶段 PH 预热 / SK 恒温 / RF 回流 / CL 冷却 |
| 2 | **加热** | 通道 T1..T4 |
| 3 | 设置 | 实测 `slot=0`、无参数回显（设置项不经蓝牙） |
| 4 | **维修** | 子功能 除胶/分层/贴合/植球 |
| 8 | 主页 | — |
> `mode` 表示**面板当前所处界面/工作模式**，不代表是否在加热——判断加热看 `[5]` 与 `[6]`。官方 APP 的 `stateStr` 把 1 与 2 的字符串表写反了，本项目按手册实现并有测试防抄。
> 计时标签随模式变：1/2/4 →「加热时间」，0/3/8 →「休眠倒计时」（用户观察 + 一致实现）。

## 4. 关键操作语义（真机闭环验证）
| 操作 | 做法 | 注意 |
|---|---|---|
| 选挡位 | `0x05 [ch]`（0..3 → T1..T4） | **会把目标温度设成该挡位预设值** |
| 开始加热（用预设） | 只发 `0x05 [ch]` | 一帧即可 |
| 开始加热（自定义目标） | 先 `0x05 [ch]`，**再** `0x03 index=4 <目标>` | 顺序反了自定义值会被预设吞掉 |
| 停止加热 | `0x05 [3]`（T4 停止通道） | 等价官方 APP；面板显示 T3；恢复需再发 `0x05 [0]` |
| 备用停止 | `0x03 index=4 0` | 同样把目标置 0 |
| 写预设/回流/维修/设备名 | `0x03` / `0x06` / `0x0B` / `0x08` | 都有 1 字节 ACK |

## 5. 功能
- 扫描 / 连接 / **断线自动重连**（三段式：系统缓存地址 → 直连地址 → 重新扫描，退避 1/2/4/8 s，总预算 45 s，等待期显示 `②直接连接 … 12s`）
- 实时监控：**单图双 Y 轴**（左轴温度红、右轴功率青）+ 鼠标悬停十字准线与读数、大字温度/目标/模式、供电/输入电压/输出功率、**功率占比进度条**
- 加热页：挡位 T1–T3 单选（回显预设）+ 自定义目标勾选 + 开始/停止（停止走 T4 通道）
- 回流焊曲线读写（8×u16）、维修参数读写（4 组）、设备名读写
- 原始帧控制台（可暂停/恢复自动滚动）、**CSV 两种格式**（完整=14 列中文表头 `时间,ISO时间,当前温度(℃),...,计时`；简洁=`时间,V(℃),A(W)`；均 UTF-8 BOM）、连接诊断页
- **输入校验**：温度 40-350℃；回流四段温度 120-180/150-220/230-300/50-80℃、时间 60-300/30-300/30-300/300-480 s；维修四组温度 60-150/60-260/60-260/40-300℃、时间均 10-300 s，任一字段越界则整条命令不下发并提示范围
- **连接可取消**：连接与重连过程中主按钮变「取消连接」，可打断正在等待的任一段，取消后立即可以重连
- **诊断页**：只读面板**并列展示「最近发送(TX)」与「最近接收(RX)」两帧**（各带时间戳与占位提示）的**字节带（每行 32 字节，单帧不折行）+ 逐字段解析表**（偏移/长度/字段/类型/原始字节/解码，覆盖 0x00/03/04/05/06/07/08/09/0A/0B/0C 的读写帧；未知命令只显示字节带；LRC 标 ok 或应为值）+ 计数；刷新节流 2 次/秒并保持滚动位置，可关闭「自动刷新」改为手工单步；另可从「原始帧控制台」点选任意一条历史帧（或双击）→ `解析选中帧`，在面板顶部**钉住**一段独立解析（轮询刷新与清空都不影响它，只有 `清除选择` 才移除）
- 不做每秒自动补读参数（避免卡顿与假提示）

## 7. 已知限制（设备固件层面，非程序缺陷）
1. **面板风扇 1–5 档完全不上报**：真实风扇转动时帧内无任何变化（唯一 bit13=1 的样本都是 `0x29BF` 哨兵常量本身）。界面固定显示「不可读（固件不上报）」。
2. **加热超时 / 温度微调 / 电源功率 / 蜂鸣 / 背光 / 休眠 / 语言 等设置项不经蓝牙**：11 条命令里没有能读写它们的；「加热超时」的剩余只能从 `W2` 读到。
3. **启动回流焊 / 启动维修没有命令**：`0x06`/`0x0B` 只写参数，启动需面板操作；「停止」可用 T4 停止通道。
4. `mode=3` 时挡位字段含义未明（实测恒 0）；`[5]` 只观测到 `0x00`/`0x02`。
5. 计时的 `SS=60..63` 在真机上是否会出现（会不会闪 OFF）尚未观测，模拟设备已按「跳过非法秒」处理。
6. 手机 APP 与 PC 同时连同一台设备会互相抢占；程序只能退避重连并提示。

## 8. 排障
- **扫描不到 / 连接失败**：先退出手机 atk-xtool 或关手机蓝牙；程序会自动走「缓存地址 → 直连 → 重新扫描」，45 s 预算用完会明确提示；仍失败就断电重启设备。
- **连接耗时十几秒**：属设备重新广播前的等待，状态栏会显示当前段与已用时间。
- **数值与面板不一致**：确认字段——`[0:2]` 温度、`[2]` 供电功率、`[3:5]` 输入电压、`[6]` 输出功率、`W2` 计时（64 进制）。

### 12.3 自动构建（后续加功能 / 修 bug 用这个）

    powershell -ExecutionPolicy Bypass -File packaging\build.ps1      # 或双击 packaging\build.bat

脚本做七件事，任一步失败即中止（不会产出“看起来成功”的 exe）：

1. 选解释器（默认优先 DSH 捆绑 Python，因为它带 bleak；PATH 里的 3.14 没有 bleak）
2. 依赖检查：bleak 必须存在（缺了直接报错，否则打出来的 exe 扫不到设备）；PyInstaller 缺则自动装，失败重试一次
3. unittest 全绿才继续（当前 416 项）
4. --selftest 44/44 才继续
5. 清理 build/、dist/ 后执行 PyInstaller packaging/hp20.spec
6. 把 packaging/使用说明.txt 拷进 dist/
7. packaging/verify_dist.py 验证产物：两个 exe 是否存在与体积、成品 PYZ 内省（0 个 test_* 模块、12 个应用模块齐全、不含 unittest）、hp20-cli.exe --selftest 44/44

常用参数：-SkipTests（只改文案时跳过单测）、-SkipTests -SkipSelftest（只打包）、-NoClean（增量）、-VerifyOnly（只验证现有 dist）、-Python <路径>（指定解释器）。

未来改动流程：改 winapp/ → 补 winapp/test_*.py → 先 -SkipSelftest 快速迭代 → 交付前跑全套 → 真机用 dist\hp20-cli.exe --probe <地址> 只读确认。

打包雷区与设计取舍见 packaging/README.md（winrt 必须 collect_all、构建机需要 USERPROFILE/HOME、frozen 日志目录、为什么不打包测试文件）。
### 12.4 体积说明（V 阶段新增图表导出后）

加入「保存图表 PNG/SVG」需要 Pillow，exe 从 **14.2 MB 增至约 32 MB**（模块 277 → 531）：
PyInstaller 的 Pillow hook 会连带收进 numpy 与全部 PIL 插件，这部分体积不影响功能。
若需要瘦身，可在 `packaging/hp20.spec` 里加 `excludes=['numpy', 'PIL.ImageQt', ...]`，再用 `packaging/build.ps1` 重建；
注意瘦身后必须**实际点一次「保存图表」**确认 PNG 仍能导出（当前版本已在打包版验证 `chart_export` 与 81 个 PIL 模块都在包内）。
